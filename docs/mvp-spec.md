# hutong-online MVP 规格 v0.1

状态：已收到休息室、胡同两向照片和用户本人肖像。现交付胡同两个视角、休息室一个视角；休息室咖啡机、贩卖机、三张餐桌、九把椅子均为独立素材并支持互动。咖啡杯有出杯、手持、桌面显示；侧面椅子配侧坐人物。家具缩小 20%，人物总缩小 28%，移除光圈并提供左上角玩法与互动提示。胡同支持两条连续桌排、八个座位和左右各六帧步行。当前素材仍为样稿；完整 MVP、八人身份/座位及人物习惯仍需后续制作与补充。最新实现与验证详见 art-pass-04.md；前三轮记录保留。

本规格以本次讨论为准。新项目重新建立角色、账号、素材与世界；cyber-hutong 只用于分析旧版体验问题。

配套文档：[素材清单](asset-manifest.md)、[资料提交清单](input-checklist.md)。

## 1. 产品目标与边界

为公司八位固定成员建立可以亲自进入的像素平行办公室。熟悉的人、真实空间、可信的日常互动是主要乐趣。

- 平台：电脑浏览器，优先 Chrome / Edge；首版完成后验证 Firefox、Safari 桌面体验。
- 画面：元气骑士式固定斜俯视；二维精灵、家具体积和动态遮挡表现纵深。胡同支持两个相反的固定视角，V 切换；切换保留真实座位、世界位置与控制权，没有连续旋转镜头。
- 气质：真实办公室的像素平行世界，配色与生活细节来自照片。
- 人数：八个固定角色，最多八人同时在线，专属账号控制本人角色。
- 场景：真实胡同、真实休息室、虚构娱乐室。
- 控制：在线由本人控制，离线由规则与模型共同驱动。
- MVP 的人物“蒸馏”：结构化档案、说话样例与游戏记忆；本阶段不进行模型微调。
- 游戏世界为主画面；地图、背包、聊天与档案按需打开，不做卡片式仪表盘或装饰性品牌外壳。

首版边界：文字交流、固定日常穿搭、有限物品、网页小游戏入口。战斗、开放世界、声音克隆、经济系统、换装、自由装修、手机触控与外部小游戏成绩同步均留到后续。

## 2. 进入游戏后的完整体验

1. 本人通过一次性邀请码激活自己的账号，设置密码，绑定固定角色。
2. 登录后出现在胡同入口或上次保存的位置，看见同场同事和分身活动。
3. 用 WASD / 方向键移动。靠近可操作对象时出现名称和 E 提示。
4. 到本人工位坐下、使用电脑，或经过门口进入休息室。
5. 制作咖啡、拿零食、坐下休息，向附近同事聊天或发出结伴邀请。
6. 给同事递咖啡，看到真实的拿取、移动、交付和回应过程。
7. 进入娱乐室，靠近像素蜘蛛并按 E，在新标签打开蜘蛛纸牌。
8. 返回游戏页面继续控制角色；浏览器切换焦点时清除移动输入。
9. 离线后分身接管。再次登录时查看最近重要经历，并继续本人操作。

在线角色不会被模型代言。分身回复在对话里标明来源；标识保持简短，不占据场景主体。

## 3. 场景与内容

| 场景 | 布局依据 | 必须呈现 | 互动对象 |
| --- | --- | --- | --- |
| 胡同 | 新提供的照片和八人座位对应 | 两排工位、真实通道、标志墙面、家具及个人辨识物 | 本人工位、椅子、电脑、同事、出入口 |
| 休息室 | 新提供的照片 | 实际装修配色、设备与桌椅关系 | 咖啡机、零食取用点、公共座椅、同事、出入口 |
| 娱乐室 | 统一美术基准下的原创房间 | 清楚可走的通道、三个游戏代表物件 | 蜘蛛纸牌、扫雷、2048 入口 |

胡同与休息室保持真实空间关系和座位归属，通过俯视转换表达，不擅自改成另一套办公室。第一批照片已明确：胡同只保留靠墙八个工位，两侧各四个，椅子位于桌子内侧，中间留走道；不改成中间相向桌岛。其余照片拆解见 reference-breakdown.md。

固定镜头随房间尺寸采用全景或边界内跟随。若地图超出视窗，跟随本人；小房间保持固定视窗。房间出入口支持往返，无额外电梯场景。

胡同采用 cyber-hutong 双视角作为机位参考：文化墙一侧与反向机位。只参考机位和尺寸关系，人物身份、座位归属不从旧代码迁移。两侧桌面各是一个连续对象，椅子与电脑各八个独立对象。当前世界坐标为 640×360，所有图层统一在 320×180 画布渲染，再整体最近邻放大；运行比例和源 PNG 导出尺寸分开记录，详见 art-pass-02.md。

娱乐室默认提供三个入口：蜘蛛纸牌已由用户提出；扫雷、2048 是可替换的补充默认项。首轮先验收蜘蛛入口，再加入另外两个。

默认外链：

- [蜘蛛纸牌](https://solitaired.com/spider-solitaire)
- [扫雷](https://minesweeperonline.com/)
- [2048](https://play2048.co/)

外链配置可以替换网址与代表素材。打开新标签时角色进入“玩小游戏”状态，原页面保留角色控制权；返回后恢复。只有实际断开连接超过宽限期才交给 Agent。服务器不猜测外部游戏是否通关。

## 4. 操作与界面

| 操作 | 按键 / 行为 |
| --- | --- |
| 移动 | WASD / 方向键，支持斜向输入，斜向速度归一化 |
| 胡同视角 | V / 视角按钮；另一侧观察同一个空间，方向键始终按屏幕方向移动 |
| 附近交互 | E；多个目标时显示目标选择，再显示该对象可用动作 |
| 关闭 / 取消 | Esc；取消尚未完成的制作或未接受邀请 |
| 地图 | M；显示三个场景与所在位置，不能点击任意位置传送 |
| 背包 | B；查看、使用当前物品 |
| 我的经历 | J；查看近期事件与分身记录 |
| 对话 | 在交互菜单选择聊天；Enter 发送文字 |

附近交互半径初始为一个地图格，具体逻辑像素尺寸随样板一起锁定。提示选择最近的有效对象；多目标情况下由本人选择，不把距离相近的人或家具误触为同一对象。

聊天与面板聚焦时停止移动。E 按下打开菜单后，如果小游戏需要新标签，提供直接可点击/可键盘确认的“打开游戏”动作，确保在用户输入事件内启动；被浏览器阻止时保留可点击链接。

HUD 只保留本人名字与控制状态、在线人数、最近交互提示及地图/背包/经历入口。中文采用清晰的正常文字渲染，边框与按钮沿用游戏像素风格。

## 5. 首版互动规格

下表中的时间与容量为试玩默认值，集中配置；真实人物习惯优先影响选择和回应。

| 互动 | 触发与流程 | 动画与对象状态 | 完成结果 / 中断 |
| --- | --- | --- | --- |
| 坐下工作 | 本人靠近自己的空椅，选择工作 | 对齐座位、播放入座、切换坐姿/打字；电脑亮屏 | 座位独占；起身释放；断线接管保持可继续的状态 |
| 起身 | 坐姿时操作或开始移动 | 从座位到对应可走站位 | 恢复移动；站位不能位于桌子碰撞区 |
| 制作咖啡 | 到咖啡机操作点，选择制作，等待 3 秒 | 咖啡机工作帧、取杯动作 | 完成后得到一杯咖啡；取消时没有产出；设备同一时刻一人使用 |
| 取零食 | 到实际取用点选择领取 | 伸手、取用点反馈 | 增加一份零食；背包满时提示；重复输入不重复领取 |
| 使用物品 | 背包选择咖啡/零食，选择使用 | 杯子或零食附着到手部，播放饮用/进食 | 一份物品只消耗一次；不引入饥饿、疲劳条或属性奖励 |
| 给同事物品 | 持有物品并靠近对方，选择赠送 | 转向、伸手、道具从赠送者到接收者 | 在线接收者接受/拒绝，30 秒过期；分身按偏好回应；接受后原子转移 |
| 聊天 | 同场靠近，选择聊天 | 双方面向与气泡；展开文字对话 | 真人本人发送；分身使用对应人物档案；离场后结束附近聊天 |
| 一起休息 | 向同场同事发邀请，对方接受 | 等待回应、前往休息室、就座或站聊 | 真人自行移动，分身寻路；90 秒未到齐则结束；可随时退出 |
| 公共就座 | 到休息室空座位选择坐下 | 座位匹配坐姿 | 单人占用；可自由站起；满座不强制挤入 |
| 网页小游戏 | 到代表对象旁 E，再确认打开 | 对象高亮、角色玩游戏状态 | 新标签打开；返回继续游戏；不获得未验证的外部通关奖励 |

背包初始为四格，每格同类物品最多五份。首版物品为咖啡、零食；水杯或其他饮品依照片与真实习惯补充。物品免费，不设置每日领取任务。制作/领取设置短操作冷却，避免按键连发。

赠送在等待接受时预留物品；拒绝、过期或中断后解除预留。完成转移和事件记录在同一事务中执行。离线角色不会在后台无限取物品或重复向同一个人赠送；相同赠送双方至少间隔 30 分钟。

第一条完整互动链：工位起身 → 去休息室 → 制作咖啡 → 手持咖啡 → 找到第二个角色 → 递交 → 收下或婉拒 → 留下一条真实完成的游戏经历。

个人行为如打电话、刷手机、固定给某人买咖啡，只有在新资料明确提供后才加入；先复用基础动作，需要表现差异时再制作专属动作。

## 6. 人物、记忆与 Agent

### 6.1 每人独立的资料

- 身份：显示名、稳定角色 ID、照片来源、座位。
- 外貌：发型、眼镜、日常服装、可辨识配饰；只记录可见且已确认的信息。
- 习惯：经常做的事、不喜欢做的事、时间倾向、可自主执行的行动。
- 说话：典型短句、长度、口头禅、标点与表情用法、不同情境下的表达样例。
- 关系：明确提供的同事互动与称呼，不由游戏系统猜测现实关系。
- 游戏记忆：游戏中实际发生的事件、参与者和可见范围。

本人档案只由用户提供或本人编辑。游戏记忆不会自动覆盖本人档案。公共活动可用于公共互动；私聊仅用于对应参与者。主人可查看、修正或删除错误记忆。

### 6.2 规则与模型分工

规则负责选择普通日常任务、寻路、坐下、工作、制作、休息和完成互动。个人偏好影响权重与持续时间，避免每个人都按同一顺序绕房间。

模型在允许行动中选择关键动作并生成少量对白。每次输入仅包含该角色档案、当前可见世界、少量相关记忆及合法行动；模型不能提交任意坐标、捏造库存或执行不存在的活动。

模型输出包含合法行动 ID、可选目标、简短对白与表情。服务端验证后执行；对白先短后长，公共气泡最多两句，避免在场景中刷长文。

### 6.3 在线人数与频率

令 N 为拥有有效控制连接的真人数量，范围 0–8。后台 AI 事件机会间隔为：

`T(N) = 900 / (1 + 0.5 * N) 秒`，加入 ±20% 随机变化。

| N | 基准间隔 |
| --- | --- |
| 0 | 15 分钟 |
| 1 | 10 分钟 |
| 2 | 7.5 分钟 |
| 3 | 6 分钟 |
| 4 | 5 分钟 |
| 5 | 约 4.3 分钟 |
| 6 | 3.75 分钟 |
| 7 | 约 3.3 分钟 |
| 8 | 自主 AI 事件停止 |

这是整个世界共享的机会，不是八个人各调用一次。调度时选一个适合活动的离线角色；没有合法情境、角色繁忙、冷却未结束时跳过，不消耗模型额度。

有人在线时，分身优先在有人活动的空间产生可见互动；无人在线时用低频世界模拟推进日常。普通规则每 60–180 秒评估下一任务，持续工作/休息可以保持数分钟，动画与位置更新不调用模型。

真人主动聊天优先处理，不等待后台事件时间。自主对话每次最多生成两名离线参与者的三个短回合；结束后不会因收到 AI 对白再次自动触发模型。相同双方自主聊天至少冷却 10 分钟。

### 6.4 额度与回退

- 后台每日最多 64 次模型请求，八人共享，日期使用 Asia/Shanghai。
- 预算初始设为 128,000 输入+输出 tokens / 天；发出请求前预留额度，完成后按返回用量核对，无法确定用量的请求保留预留额。
- 单次后台上下文预算 1,800 tokens、最大输出 200 tokens；使用非思考模式。模型适配器采用对应分词器或保守估算并预留余量。
- 总结、重试及已发出的失败请求都占用请求次数；不进行无限自动重试。
- 后台规划同时最多一个，真人聊天使用独立队列；请求 10 秒超时。
- 主动聊天独立限流和统计，默认每人每日 40 次模型回复；本规则只限制模型回复，不限制真人之间聊天。
- 额度不足、服务不可用、输出非法时使用规则及经确认的短句回退；移动、操作物件和存档继续可用。
- 调度参数集中在配置中，试玩后依据实际行为与账单调整。

无人在线 24 小时有 96 个基准事件机会，但每日最多发出 64 个后台请求；达到额度后仍有规则生活。这是调用上限，不是每天必须用满。

### 6.5 控制交接

- 最后一个控制连接断开后保留 60 秒宽限；期间角色停止输入，等待重连。
- 本人回来后取消待执行的自主计划与模型回复，立即取得控制。
- 每个角色同一时间只有一个控制连接；新窗口接管时旧窗口失去控制并显示说明。
- 切换小游戏新标签、聊天输入聚焦或暂时失焦只停止移动，不自动交给 Agent。
- 服务启动后角色进入规则托管；登录成员再取得控制。
- 只有常驻服务运行时世界才会继续。服务停机期间暂停，不通过补算历史对白消耗大量模型请求。

## 7. 技术栈与实现边界

| 部分 | 选择 | 职责 |
| --- | --- | --- |
| 游戏客户端 | Phaser 4 + TypeScript + Vite | 场景、精灵、动画、镜头、输入与像素渲染 |
| 页面面板 | TypeScript + HTML/CSS | 登录、对话、背包、经历、档案；首版无需 React |
| 地图 | Tiled 正交地图 JSON，嵌入 tileset | 分层、碰撞、出生点、出入口、座位与交互点 |
| 后端 | Node.js 24 LTS + Fastify | 同源静态资源、认证、档案和世界接口 |
| 同步 | ws WebSocket，浏览器原生 WebSocket | 行动意图、快照、事件与重连 |
| 存档 | SQLite，Node 内置 node:sqlite | 账号、状态、物品、记录、档案与额度 |
| 模型 | 服务端可配置适配器 | 服务商、模型名、接口地址和 Key 由环境配置；不写进客户端 |
| 验证 | 逻辑测试 + 浏览器操作验证 | 同步、交接、互动事务、动画及真实操作体验 |
| 部署 | 单台常驻 Node 服务 + 持久磁盘 + HTTPS | 一个权威世界、定时 Agent、存档与备份 |

选择依据与官方资料：

- [Phaser 官方 TypeScript / Vite 模板](https://github.com/phaserjs/template-vite-ts)：当前模板依赖 Phaser 4.0.0，作为初始化基线；首次安装固定锁文件。
- [Phaser API 文档](https://docs.phaser.io/)：地图对象、精灵、动画和像素镜头能力。
- [Tiled 对象层](https://doc.mapeditor.org/en/stable/manual/objects/)：碰撞、交互点和对象属性。
- [Fastify](https://fastify.dev/docs/latest/)、[ws](https://github.com/websockets/ws)、[Node SQLite](https://nodejs.org/api/sqlite.html)。
- [Node 版本状态](https://nodejs.org/en/about/previous-releases)：项目基线为 Node 24 LTS；当前本机检测到 Node 22.17.0，正式初始化时配置项目运行环境。

### 7.1 移动与渲染

- 服务端以 20 Hz 更新世界，约 10 Hz 广播同场状态；客户端独立渲染，目标 60 FPS。
- 本人使用客户端预测、服务端校正与输入序号；其他角色插值，避免每次收到位置后直接跳动。
- 服务端验证速度、家具碰撞、交互距离、座位占用与场景出口。
- 角色碰撞范围以脚底为主；角色之间不使用阻塞碰撞，避免八人在狭窄通道相互卡住。
- NPC 使用 A* 寻路，避免斜穿家具拐角；寻路队列和模型队列均不阻塞世界更新。
- 家具和人物按脚底/基底深度排序，桌面、椅背或较大家具必要时拆分前后层。
- 最近邻整数倍放大、像素对齐；输入坐标与逻辑坐标使用同一变换。

### 7.2 数据与接口

客户端仅提交移动、停止、互动、对话、邀请回应等意图；角色身份取自会话，不能通过请求选择他人的角色。

服务端快照包含世界 tick、角色位置/朝向/动作/控制模式、对象状态、座位占用、有效邀请与事件。重连发送完整快照，随后继续增量事件。

共享配置分为 SceneConfig、AssetDefinition、InteractableDefinition、CharacterProfile、MinigameDefinition。动作使用合法 ID；地图物件都有稳定 ID、操作站位、碰撞范围和所需素材状态。

数据库保存账号与会话、角色档案、背包、对象状态、邀请/活动、聊天、游戏记忆及模型用量。位置每 10 秒检查点保存；物品转移、互动结果和聊天即时持久化。重启可能恢复到最近检查点位置，但不会重复交付物品或消耗邀请码。

原始人物和场景照片保存在不对外提供的参考目录；客户端只加载通过验收的游戏素材。源照片、姓名对应表和生成版本记录分开维护，避免将照片当作前端资源发布。

激活采用八个一次性邀请码与固定成员绑定，密码使用加盐哈希，会话使用 HttpOnly Cookie。正式账号首次内部试玩时创建；制作样板使用隔离测试身份。

### 7.3 实现顺序

源码按 client、server、shared 分开；游戏渲染、DOM 面板、世界模拟、Agent 调度和模型适配器各自独立。首版一个进程和一个 SQLite 世界，不引入多实例协调、微服务或向量数据库。

先完成单人本地样板，再补共享世界与人物资料，最后接模型和后台调度。美术生成、模型和公网主机不依赖同一服务商。

## 9. MVP 验收清单

- [ ] 八个身份与照片逐一对应；座位归属符合新提供资料。
- [ ] 胡同和休息室保留可辨识的布局、配色与关键细节。
- [ ] 人物、家具与物件像素尺度一致；无混合模糊/高清纹理；无绿底边缘。
- [ ] 四向走路连续，脚底不漂移；坐姿与椅子一致，桌前桌后遮挡正确。
- [ ] 键盘移动即时响应；模拟 150–300 ms 网络延迟时仍可操作，停止后能正确校正。
- [ ] 八人同场时目标 60 FPS；用一台实际办公电脑记录帧时间，模型等待时不降低移动响应。
- [ ] 三个场景可往返；重连恢复同一角色，不产生分身。
- [ ] 空椅竞争只有一人成功；制作取消无产出；赠送拒绝/过期无丢失；重复输入不重复发物品。
- [ ] 真人聊天由本人发送；Agent 回复明确来源；私人记忆不出现在公共对白。
- [ ] 本人接管取消旧自主任务和在途回复；模型失败时规则继续活动。
- [ ] 0–8 在线人数调度符合配置；64 次和 token 额度包含并发预留、失败和重试，重启后不重置当日额度。
- [ ] 外链成功打开；弹窗阻止时有可用链接；切换标签停止移动，返回位置保留。
- [ ] 重启保存角色档案、物品和事件；未完成活动安全结束，已经完成的事件不重放。
- [ ] 游戏界面没有整页浮动白色圆角容器、虚构 AI 标识、装饰性导航或大量渐变阴影。

## 10. 仍需真实资料确定的内容

已定：平台、视角、三个场景定位、控制方式、外链小游戏方式、AI 辅助美术、分阶段样板、后台每日 64 次。

待资料确定：八人身份及照片对应、每人穿搭/辨识物、准确工位和家具位置、休息室实际设备、个人习惯与语气、模型服务商和内部上线环境。

本规格新增的容量、持续时间、补充小游戏和技术数值均是明确标注的实施默认值；真实参考进入后记录修改，先验证样板再冻结美术尺寸和批量生产。
