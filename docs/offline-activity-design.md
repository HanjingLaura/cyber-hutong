# 离线活动与值得回看的经历（已启用）

背景生活与经历分开调度。人物持续在真实房间中行动，但走路、办公、领取咖啡不逐项当作故事。经历来自真正执行并有结果的活动；不凭空生成故事，不修改已有记录。

八人都离线时，整个空间共用一个活动发起时钟，每 20～30 分钟尝试发起一次值得回看的活动，随机间隔避免固定整点。默认规则权重单人约 60%，共同活动约 40%，当前共同活动参与两人；百炼启用后可从有效候选中选择。每次只发起一个，现有活动尚未结束时延后；人数增加不把整个空间的故事量直接乘以人数。部分玩家在线时也只选择空闲离线人物。

日常活动保持 30～90 分钟办公、10～25 分钟休息或个人爱好等不同持续时间，依角色已有习惯选择，不新增未经确认的习惯。社交邀请、玩家上线、物品冲突优先打断计划。个人任务和团队任务不能同时占用同一人物。

单人候选例子：抽到此前没有的扭蛋、完成拼豆作品、小游戏产生新成绩、发现彩蛋。多人候选例子：邀请被接受并实际碰面后一起休息、赠送被接受、共同参与现有房间活动。候选都需真正走路、占用设备、完成物品事务或保存作品/成绩，不能只记录一句描述来代替动作。

选择权重由兴趣匹配、当前状态/手持物、参与者空闲程度、过去参与次数与新鲜感组成。同一组合与同类内容设置冷却，优先让近期没有参加的人获得机会。位置接近或同处一个房间本身不足以构成故事。

记录在活动出现结果时触发，保存活动参与者和真实场景状态；一个共同活动在参与者各自经历中可见，对应同一事件。多人活动没有成行则不冒充完成，真正的送礼拒绝等互动结果仍保留。平均每小时 2～3 次为调度目标，不强迫一定发生，也不删除超过数量的事件。

当前实现：统一持久化时钟、活动状态机、人物权重及两小时组合冷却；三个完整活动为抽扭蛋、一起休息和送咖啡。作品、成绩及三人活动属于后续扩展，不计为本轮已实现。代码在 `server/director.mjs`，模型接口在 `server/llm.mjs`。
