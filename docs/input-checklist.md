# hutong-online 开始制作前的资料清单

先发第一批即可，不要求八人所有资料一次到齐。照片可以直接发在当前聊天，或给出本机文件夹的绝对路径。

## 1. 第一批：收到这些即可开始样板

### 胡同

- [ ] 两个相反方向的全景，能看清工位、通道、墙面与入口；如果一张拍不全，每方向补一张。
- [ ] 一张工位近照，能看清桌子、椅子和电脑的关系。
- [ ] 一张墙面标志或你最想保留细节的近照。
- [ ] 说明哪些东西必须保留，照片中哪些临时杂物可以省略。

不需要精确测量。提供大致的桌子数量、通道关系和一份手画布局会更准确。

### 第一个人物：建议先做你

- [ ] 明确名字/游戏显示名，并标注照片对应的人。
- [ ] 一张清晰正面照。
- [ ] 一张日常穿搭的半身或全身照；如果只提供脸照，另说明首版想穿什么。
- [ ] 有侧面或背面照可补充，没有也可以先开始。
- [ ] 指出想保留的辨识特征：发型、眼镜、饰品、衣服等。
- [ ] 说明你坐哪个工位。

收到以上资料后，我开始：照片拆解 → 美术基准与素材分层 → 一个角色/一套家具 → 可移动、可坐下的浏览器样板。

第一阶段不需要你先购买服务器、提供模型 Key、整理全部聊天记录或制作任何像素图。

## 2. 第二批：打通两人日常互动

- [ ] 第二个人的姓名与照片，按相同方式标注。
- [ ] 休息室 2–4 张不同方向全景。
- [ ] 咖啡机、零食取用点、桌椅、柜子/冰箱等主要对象的近照。
- [ ] 两人的日常习惯，各列 3–5 条。
- [ ] 两人的真实说话样例，各 10–20 条短句；有情境说明更好。
- [ ] 两人现实中会发生的 2–3 个互动，如送咖啡、一起休息、互相打趣。
- [ ] 模型服务商名称或想用的模型；Key 在接入阶段配置到本地环境文件。

这一批用于验证完整咖啡链、聊天与人物感、两人联机和离线接管。没有模型配置时可以先验证动作、规则和预设短句。

## 3. 第三批：完整八人版

- [ ] 八人姓名/显示名清单。
- [ ] 每人对应照片，逐一明确对应，不依靠外貌猜名字。
- [ ] 八人座位对应；可以在全景图上写名字，或发文字/手画示意。
- [ ] 每人一份简短人物资料，使用下方模板。
- [ ] 每人最多一个想放进工位的辨识物，以及照片或文字说明。
- [ ] 希望加入的真实日常事件列表，说明参与者和典型回应。
- [ ] 娱乐室小游戏偏好。默认蜘蛛纸牌、扫雷、2048；有指定网页就提供网址。

小游戏对象与娱乐室由我按统一美术基准设计，无需提供真实娱乐室照片。

## 4. 人物资料模板：可直接复制填写

```text
名字 / 游戏显示名：
照片对应：
工位位置：
首版服装与外貌辨识点：
想放在桌上的一个东西：

经常做的事（3–5条）：
不喜欢或不希望分身做的事：
有明确时间习惯的事情：
经常一起活动的人，以及具体做什么：

说话特点（例如句子长短、口头禅、表情习惯）：
真实表达样例（10–20条）：
1. 情境：……；原话：……
2. 情境：……；原话：……

别人给我咖啡时，通常会怎么回应：
别人邀请我休息时，通常会怎么回应：
我可能主动找同事聊什么：

允许分身自主做的事：
需要本人确认的事：
人物出稿后最需要检查的地方：
```

先写你知道的部分。没有资料的行为保留为空，不把猜测写进本人档案。说话样例最好带情境，不能只靠几个性格形容词。

## 5. 事件资料模板

```text
事件名字：
谁会发起：
找谁：
一般在哪里 / 什么时间：
现实里通常怎么做：
每个人典型会说什么：
可能接受 / 拒绝的情况：
哪些部分必须还原，哪些可以游戏化：
```

例子的用途是描述你们真实会做的事；具体名字、习惯和对白由你提供。

## 6. 照片交付建议

- 优先原图；清晰的手机照片就可以，不需要专业摄影。
- 场景优先全景与家具位置，随后补细节，不需要先抠图。
- 人物优先脸部与日常穿搭；不必为四向动画专门拍全套动作。
- 每张人物照片附名字。如果一张有多人，明确标注每个人位置和名字。
- 从本机文件夹读取时，可以采用“人物/名字”和“场景/胡同、休息室”分类，也可以保留现有文件名再提供对应说明。

## 7. 内部上线阶段再需要的资料

- 常驻主机或愿意持续开机的电脑；世界只能在服务运行时继续。
- 同事通过公司局域网还是公网链接访问。
- 公网访问时的域名/主机配置；届时再做部署准备。

现阶段优先发：胡同两个方向全景＋一个工位近照＋你的正面/穿搭照片＋名字与座位。其余可在样板制作期间逐步补充。
