# 第一轮美术与交互样板 · 2026-10-01

## 此轮结果

照片中的胡同转为固定斜俯视的浏览器样板：两条靠左右墙的连续桌面，左右各四把独立椅子、四台独立电脑，中间通道。只使用用户明确标注为本人的第四张照片做角色；照片中的其他人员未作为角色生成。

支持 WASD / 方向键移动、停步、家具碰撞、靠近座位按 E 坐下办公、电脑亮屏、左右打字、E / Esc 起身。人物、桌子、椅子、电脑均不在基础背景里。右侧可逐层隐藏，并显示 L1–L4 / R1–R4 座位点。从尽头墙向入口编号；没有绑定真实人员。

正式游戏仍按 MVP 规格的 640×360 视窗推进；此轮为了同时观察完整八个工位，使用 640×640 全景检视，人物站立展示高度 54 逻辑像素。这些检视尺寸不是新的批量生产标准。

## 实测结果

- npm run build：TypeScript 检查和 Vite 生产构建通过。当前引擎打包有大块体积提示；未把生成样稿当作已优化的上线资源。
- 浏览器真实键盘操作：W 与方向键移动正常，松键停步，左侧椅子碰撞能阻挡。
- 逐一到达并坐下八个座位：L4、R4、R3、R2、R1、L1、L2、L3；左右朝向和起身返回通道有效。
- 轻按 E 曾漏触发，改为按键事件触发后通过相同操作复测。避免依赖帧内按下/抬起标志。
- 背景、桌面开关测试通过，独立对象仍可显示。开关仅用于图层检视，不解除碰撞。
- 左、右坐姿截图已人工查看，人物与椅背分层有效。电脑和椅子没有重复画在背景中。
- 无通用 SaaS 外壳、装饰品牌图标、渐变光斑或大白色圆角整页容器；界面围绕游戏操作和素材检查。
- 原始参考照片不在生产构建中；开发服务器也拒绝读取 references/private/。

## 仍需打磨的美术问题

当前为可操作的美术样板。基础地毯、桌子、人物的原始像素密度还没有锁定为统一生产网格；正式素材需统一轮廓粗细、块面与纹理密度。走路四帧的步幅区别不够稳定，循环仍需整理。打字帧的手型与像素轮廓也需要进一步统一，不把此轮当作最终动画验收。

右侧文化墙保留整体构图，文字需要用独立排版恢复真实内容。未补入桌面植物、个人摆件和衣物，避免在未确认归属时猜测。入座/起身当前为状态切换，完整 MVP 的伸手、拿杯、消费和过渡动作仍按后续批次制作。

## 下一批

1. 用户补充显示名、座位；可选补充固定日常裤鞋，校正本人服装。
2. 根据这份样板调整并锁定人物、家具、背景的统一像素标准，再批量制作。
3. 休息室采用同一标准：背景仅白墙、灰地毯、固定 Go! 墙饰；台面、圆桌、青绿椅独立，咖啡机、橙色零食柜、银色冰箱、玻璃门独立有状态。照片可见三张白圆桌，椅子数量不从遮挡区域猜测。
4. 加入第二位同事的明确照片与说话习惯，实现拿咖啡、递交、回应的最小互动循环。

完整多人和分身逻辑详见 mvp-spec.md。样板不包含登录、联网、自动分身、记忆、聊天或其他七个人物。
