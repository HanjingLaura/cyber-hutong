# 街道、校园碰撞与方向控制

用户确认的问题是穿过路边物体、骑进背景，并要求电动车及滑板统一用 WASD／方向键直接上下左右移动。

此前两个场景都按 x35..605/y190..345 的矩形判断人物脚下一个点，包含街道背景、校园绿化和建筑。校园路锥只在前端阻挡。现在 `shared/outdoor-collision.mjs` 定义实际前景地面、步行脚印、完整车身与滑板占地；`sceneWalkable`、客户端运动和服务端骑乘校验复用这些规则。街道前景为 x10..630/y226..352；校园按广场铺装轮廓设置多边形，路锥几何来自同一清单。

电动车按宽92的完整车体及7px地面纵深检测，服务端同时检查移动路径；滑板检测朝向投影、板面边缘和转向扫掠。转向空间不足时保留合法朝向先移出，有空间再转，避免贴边按方向无法走；同轴反向不作虚构半圈旋转。轮圈路标已移到新区域内。

两种载具共用方向运动实现，斜向归一化，松键快速停稳；删除油门、刹车、蹬地和按左右旋转的旧控制逻辑。F保留滑板坐姿，停稳E上下车。触屏摇杆沿用同一方向键事件路径。旧《ride-handling-2026-10-15.md》的油门控制说明已由本次方案取代。

旧越界车辆会迁移到合法完整车身位置并同步乘员，旧步行存档由位置恢复处理。上板采用停板中心，避免把完整滑板放到仅允许步行的边缘；下板校正人的脚印位置。上车后清除旧步行到达标记，避免持久化仍固定在旧位置。人物原素材和两人车座加一人车筐布局保留。
