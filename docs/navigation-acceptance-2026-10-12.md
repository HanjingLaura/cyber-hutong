## 修复与复现

- 最终位置上报：地图设置 `transitioning` 后，普通上报会跳过。切换专用上报现在明确等待 HTTP 确认，再提交 transition；期间普通 HTTP 与 Party 动作停止发送。
- 重复按钮监听：休息室初始化 → shutdown → 再初始化 → 点击一次互动。无弹窗、场景 active；诊断替换 interact 计数，修复前调用 2 次，修复后 1 次。此复现只验证事件调用次数，不等同于全部按钮问题已解决。持久 DOM 控件的监听现在随场景 shutdown 移除；休眠时不执行旧场景操作。
- 地图：缩略图只选择；独立“进入”确认。快捷模式默认关闭，设置保存于浏览器；只有距离校验可以跳过，座位、互动、控制权仍由服务端校验。站在货架旁不等于正在互动。
- 失败恢复：素材失败/超时不提交切换；请求响应丢失时读取自己的服务器位置。若位置查询也失败，停止发送旧场景坐标，等待实时快照恢复。busy 和关闭按钮最终都会解锁。

## 已验证

- 专项测试：17 项通过。包括最终上报、并发确认、重复提交、素材失败/超时、恢复渲染失败、快捷模式边界和监听清理。
- 服务端真实 API：50 次切换覆盖全部 15 个房间；每次查询服务器场景、入口和座位。
- 浏览器：50 次连续地图切换，穿插聊天与人物面板开关；未观察到切换锁残留，焦点返回 world。
- 浏览器故障注入：上游提交后丢弃响应；恢复到提交后的房间。再丢弃位置查询响应，随后通过 SSE 恢复。
- 390×844 与 1280×800 检查：地图无横向溢出；进入按钮 sticky，触屏高度 44px。
- 设计机械检查无发现；保留既有像素主题、方角控件与实际地点名称，未引入全局设计约束中的禁用图案。
