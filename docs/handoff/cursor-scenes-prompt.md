## 目标和实现顺序

先完成可玩的“胡同单场景”纵向闭环，再扩展多场景。
本轮优先桌面网页，用户明确暂不要求手机适配。不要为手机适配推迟交付。
先列简短计划，随后实施、测试，不只交付设计稿。
保持原有栈；可使用原生 Canvas 2D。不要为了玩法顺便重写整套前端。

1. 场景数据与坐标：1280×720 逻辑尺寸，背景、可走多边形、碰撞区、
   出入口、交互点、座位锚点、前景遮挡均配置化。屏幕 resize 不改变逻辑坐标。
2. 角色渲染：复用八张现有角色表，裁切实际非绿底范围，统一脚底锚点。
   不按整张图比例缩放，不把 6 个不同姿态误当成完整 6 帧行走动画。
   原图缺帧时用明确的有限动画方案，不能声称有四向完整走路。
   站立角色建议先以约 72–96 逻辑像素高校准，再根据桌椅比例统一调整。
   原始文件保持不变；绿幕去除不能伤及人物/巴斯光年衣服中的绿色。
3. 输入和碰撞：WASD/方向键移动，点击可走位置寻路；触控移动留待后续。
   靠近目标才显示 E 交互提示；Esc 关闭对话/菜单，输入框聚焦时禁止移动快捷键。
   交互参考元气骑士的直接操作和反馈，不复制其素材，不添加战斗系统。
4. 服务端权威世界：客户端只发送带 seq 的意图，不上报可被信任的最终位置。
   服务端鉴权、速度限制、碰撞、交互距离、场景归属、门口条件、重复意图去重。
   使用适合长连接的常驻服务；同步状态，客户端插值。同一角色只能有一个控制租约，
   多标签页不得复制角色；断线有约 15 秒接管宽限，重连恢复快照。
5. 座位与交互：坐下/起身、工位活动、靠近人物打开现有私聊；
   前景遮挡/脚底 y 排序正确，含椅子的背景不能再重复绘制椅子。
6. 接入 BehaviorEngine、WorldRepository 和幂等 outbox 消费者：
   持久化角色场景/位置/动作、邀请、事件和每日去重。寻路抵达后才能推进事件。
   禁止浏览器自行声称到达、直接调用可信 update 回调或任意改变他人状态。
7. 胡同闭环验证通过后接多场景、离线行为和特殊角色。

## 离线驱动与 LLM

第一版用“日程 + 偏好权重 + 状态机”驱动离线人物。
行为规则控制去哪、做什么、冷却、占位和邀请；寻路系统控制如何抵达。
LLM 仅做可选对白，不能决定鉴权、位置、领取权、别人是否接受邀请。
不每帧调用模型；限频、限轮数、超时和失败回退必须保留。
真人接管立即取消自动行动，迟到的模型回复/寻路结果不得覆盖手动操作。
全员离线可以停止实时广播；恢复按当前状态继续，不瞬间重放整晚事件。

## 持久化与部署边界

当前 api/index.mjs 用 Vercel /tmp SQLite，只是临时预览，不能存真实注册记录。
正式多人玩法请先确定常驻 Node + 持久卷，或外部数据库 + 长连接服务。
不可把本地 SQLite 文件上传到 Git，不提交 .env、领取码、重置码、会话或 API Key。
不要自动覆盖/清空现有账号；迁移必须保留数据并可回退。
需用户提供部署权限或基础设施时说明缺口，不伪造成功。
