# 平行空间生活

玩家经历是实际事件的追加记录，只有本人能查看，没有纠正、编辑或删除入口/API。J 打开画面回看，B 打开背包。事件发生时保存房间、人物位置、朝向、动作、手持物和场景物件的状态，使用游戏素材还原；左右箭头翻阅，底部小画面直接选择。时间与一句说明附在画面上。旧记录没有场景快照则明确显示未留下画面，不补造事件。登录会提示已有经历。资料由管理员通过 `node scripts/profiles.mjs 私有资料.json` 维护，游戏端不提供资料编辑或展示。私有文件不要提交到仓库。

背包四格，每格同名且调料相同的物品最多五件；手持物独立。收起、取出和吃喝以服务端事务执行，同一次请求重试不会重复扣除。赠送保留在原主人手里并锁定用途，30 秒内对方接受才交付；婉拒、取消、超时均不丢失物品。邀请一起休息可接受、婉拒和取消，90 秒内双方实际到达休息室附近才算碰面。在线玩家自己走，离线人物按规则赴约。

短暂断线保留控制交接宽限期，之后离线分身接手。服务端保存位置和事件；上线取消分身旧任务并接手当前位置，已坐下的角色先回到椅子旁。办公只使用自己的工位，借用别人椅子不会办公。分身在家具约束的网格上走到出口和活动位置。全空间共用一个随机 20～30 分钟的故事时钟，同一时间只执行一个活动，选择空闲的离线人物，考虑习惯、最近参与次数和组合冷却。普通办公、走路、接咖啡及仅仅处于同一房间不产生故事记录。

三个活动已接入真实流程：单人走到扭蛋机抽取并拿到物品；邀请被接受后双方走到休息室、找到空椅子一起坐下；送礼者取咖啡、走近对方并在接受后交付。物品仍通过原有事务与版本校验处理。上线或超时会中断，重启将未完成活动标记中断，不补写完成。多人结果共用事件 ID 和不可变场景快照，回看保存实际手持物、桌上物件和彩蛋可见性，按游戏深度处理家具遮挡。

## 百炼与本地启动

双击根目录 `start-game.cmd`，在隐藏输入窗口粘贴百炼 Key。脚本保存到本地 `.env.local`，验证真实调用后重启后端并打开游戏；验证失败会保留配置并显示错误。默认北京地域 `qwen-plus`，如使用其他地域需设置 `LLM_BASE_URL` 和对应模型。密钥不进入前端、日志或聊天。

模型使用后台确认资料、真实经历及当前双方私聊生成回复，也可从后端给定候选中选择活动；不能直接改变背包、座位或交易结果。默认每日最多 200 次调用、最多两个并发、单次超时 10 秒，连续失败进入冷却。额度使用持久化计数，缺少 Key、限额、异常或无效输出时继续使用规则。真实百炼调用需完成上述 Key 输入；自动测试使用模拟接口，不代表已验证真实凭据。

后台资料 JSON 示例：`{"role":"laura","habits":"用电脑开发，有时加入 Amber 和 Cora 的下楼活动。","voice":"","examples":"","confirmed":true,"autoReply":false}`。只录入提供过或确认过的事实。记录来源和待确认观察可保留在后台私有文件，尚未确认的信息不要作为已确认角色事实。

# 上线配置

本轮先准备本地版本和配置，服务器待定。服务器需有 Docker Compose、可持久化磁盘与指向服务器的域名。部署目录 `.env` 设置 `GAME_DOMAIN` 和 `HUTONG_INVITE` 后运行 `docker compose up -d --build`。Caddy 提供 HTTPS，游戏 SSE 和 API 由同一域名访问。SQLite 放在 `game-data` 卷，单实例运行。

容器每 30 秒健康检查；用 `docker compose ps` 和 `docker compose logs --tail=100 game web backups` 观察运行和备份错误。备份容器启动时及每日执行 SQLite 完整性检查和 WAL 一致性备份，不自动删除历史备份；磁盘容量和备份异地复制需在选定服务器后配置。禁止 `docker compose down -v`，这会删除游戏数据卷。

恢复：先停游戏和备份服务，将备份用 `scripts/database.mjs restore` 写入一个新数据库文件，验证 `integrity_check` 后修改 `HUTONG_DB` 指向新文件，再启动服务；不直接覆盖正在使用的数据库。原有 `npm run db:backup`、`npm run db:restore` 可用于本地。

真人验收仍需八人实际同时游玩半小时：各自登录、办公与借座、送礼接受/拒绝/超时、背包收取吃喝、休息邀约、地图出口、外部小游戏返回、刷新和断线恢复、查看自己的经历。自动负载测试不能替代真人体验验收。

本地自动验收：33 项服务端测试、八账号浏览器功能验收和三个自主活动的浏览器回看验收已通过。此前八账号 / 32 个 SSE 连接连续 1800 秒（14902 次状态更新，无错误）已通过；该长测尚未针对本轮活动调度改动重跑。浏览器验收包含画面加载、人物快照、翻页、只读历史、赠送、背包、邀约和刷新恢复。Docker Compose 配置已检查；本机 Docker 守护进程未启动，镜像尚未实际构建，正式部署待服务器确定。

事件记录维护：共享事件 ID 按账号唯一，重试不修改已有快照。普通背景动作不记录，实际送礼、邀约、抽取结果等记录不设每日硬上限。调度目标约每小时 2～3 次，有忙碌、路径阻塞或上线接管时会更少。历史只查看，不能纠正或删除。
