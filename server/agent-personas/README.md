# 八人人设（仅服务端）

每位角色一份 JSON：`laura`、`suki`、`sid`、`jilly`、`kay`、`franco`、`cora`、`amber`。目录是线上聊天 Agent 的人设来源；旧账号数据库里的前端资料不再覆盖这里的文件。服务启动时校验并加载，修改后重启本地服务或重新部署线上版本生效。

八位均已补入用户提供的资料，Jilly、Cora和Amber另有截图中的真实对话样例。本次上线八位全部启用，离线接管条件满足后按私聊或明确 @ 回复。这里的 `confirmed` 表示维护者已核对该版本资料，不再要求角色到游戏前端确认。

| 字段 | 用途 |
|---|---|
| `role` | 与文件名一致的角色英文名 |
| `source` / `sourceVersion` | 资料来源、日期或版本 |
| `voice` | 说话口吻和表达习惯 |
| `aliases` | 角色昵称。八位的昵称对应关系会一起提供给模型，帮助理解聊天里的称呼；不能与其他昵称或角色英文名重复 |
| `facts` | 已核对的事实与偏好，最多24条 |
| `examples` | 真实对话样例，最多24条；无资料时留空，不编造 |
| `rules` | 回复边界，最多20条 |
| `confirmed` | 后台已核对该版本资料 |
| `enabled` | 是否允许离线聊天接管；必须先完成资料核对 |

事实示例：

```json
{"scope":"public","text":"可以在公共频道使用的偏好"}
```

限定私聊对象的事实：

```json
{"scope":"private","peer":"sid","text":"仅用于与 Sid 的私聊"}
```

`scope: private` 且不指定 `peer` 表示所有双方私聊可用，公共频道仍不可用。对话样例使用相同的可见范围字段，并将 `text` 替换为 `context` 和 `reply`。条目可加独立 `source`；省略时沿用文件来源。

修改后运行 `npm run agents:check` 校验八份文件。无效或缺失配置会阻止服务启动，并只报告文件名，不输出资料内容。版本号由内容计算；配置变化后，旧版本尚未发送的任务会取消。

当前称呼：头哥=Franco，哥=Sid，姐=Suki，CTO/小小韩/老瑞=Laura，安博老师/博子=Amber，吉利老师/几粒老师=Jilly，co教授/小孔=Cora。CTO等在这里是用户给出的称呼，不额外推断现实职位。追星“老公”、米线“请假/禁入”、咖啡“上供”和“告状”均按群聊梗理解，不补造现实关系或新增游戏规则。

Celine是独立场景彩蛋，不占八人名额。她原有的走动、出现与座位逻辑独立保留；本地与联机场景共用 `shared/celine-speech.mjs` 的招呼。首次出现45–90秒后开口，此后每90–180秒随机一句，气泡6秒：60%“Amber 呢？”，25%“Jilly 呢？”，15%“Amber 这孩子。”。不会自动生成Amber的回复或抢占其控制权。

游戏前端没有人设入口或读取/编辑接口，只展示角色与聊天状态。离线接管仍需心跳过期后等待5分钟；本人上线取消未发送回复；私聊直接触发，公共频道明确 @ 才触发。模型失败显示失败状态，不用预设台词冒充真实模型回复。第一阶段聊天 Agent 不新增自主移动或物件操作能力。

模型调用按真人消息触发。后台活动选择、离线角色自聊与活动台词不调用模型；十天无人使用也不产生这些模型调用。Celine的固定彩蛋台词同样不耗token。没有定时模型心跳或定期总结。

全服共用持久化预算：北京时间每天最多200次调用、50,000 token预算，分别由 `LLM_DAILY_LIMIT`、`LLM_DAILY_TOKEN_LIMIT` 配置。发请求前在既有持久化事务里预留输入UTF-8字节数加输出及封装余量；成功后按提供商返回的token用量结算，缺少用量或失败时保留保守计费额度，避免并发和重启绕过预算。不需要新增数据库表或列。

单次输出上限180 token，输入上限16,000字节。只带最近6条频道内消息、最多4个可见对话样例；过大时先减少历史，再拒绝超限请求。模型失败不无限重试，排队任务10分钟过期，相同消息请求去重。后台仍可按既有规则处理世界状态，这与真实模型计费分开。

这些文件不是前端静态资源。Vercel 函数配置已包含此目录；不要将它复制到 `public/` 或 `dist/`。百炼密钥继续放服务端环境变量，不放人设文件。
