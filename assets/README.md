# 素材目录

游戏使用640×360逻辑画布和固定投影。文件名中的`v1`、`v2`等是历史命名；是否正式使用，以`src`中的引用和审计清单为准，不能按版本数字直接替换。

| 目录 | 用途 | 存放规则 |
|---|---|---|
| `drafts/` | 历史沿用的正式室内场景、家具及设备图集；也可能有未使用的候选 | 现有游戏仍从这里加载正式资源。不要因为目录叫drafts就删除、移动或换路径。背景和图集分别存放，保留原图尺寸、格位、透明度及锚点。 |
| `maps/places/` | 外部地点及会议室等独立地点背景 | 正式路径由场景、预加载和地图预览共同引用。`*-pixel-v2.png`等旁路候选不代表生产版本。 |
| `maps/memories/` | 游戏实际场景合成后的地图缩略图 | 从游戏重新截图，包含正式背景与固定家具；不是单张背景的缩小副本。隐藏角色和临时提示后拍摄。 |
| `maps/`下其他文件 | 早期地图及入口图 | 先查引用再判断用途；不自动删除。 |
| `props/` | 透明家具、小物、正式商品、游戏机内部静态外壳 | 每项保留用途明确的名称。动态玩法与状态继续由代码处理，不能在图上画假爪、假奖品或固定用户作品。`toys/`按现有索引维护商品身份。 |
| `ui/` | 工位电脑外框、壁纸及实际App图标 | 显示器屏幕开口与CSS窗口严格对齐。实际第三方logo保持原图，不用生成图替代；壁纸不烘焙按钮、时钟或图标。 |
| `characters/`、`npcs/` | 已有角色动作与NPC | 与场景美术分开维护，遵守各角色manifest与README的帧、方向、尺寸和身份约束。 |
| `metadata/` | 帧、场景及音乐元数据 | 与引用素材一起维护；不得只换图而遗漏裁切约束。 |
| `audio/`、`video/`、`tickets/` | 用户指定媒体与票券资源 | 不随场景美术刷新重生成，不替换真人、原MV或第三方标志。 |

正式素材直接保存在当前被引用的canonical路径。生成原稿、被拒候选、备份、审查截图和prompt留在`output/art-refresh/`；游戏不要引用这些审查文件。只有审查通过后才替换正式资源，不在`assets`里不断新增几份无法区分的“final”文件。

透明图必须是真实alpha，不能带棋盘格或白底。图集内各物件不得跨格；运行时按alpha>192找轮廓，细碎低透明边缘会干扰裁切。先看实际frame和目标显示尺寸，再看640×360场景合成。尺寸归一可用nearest采样，不能用简单滤镜冒充重新生成。

运行`node scripts/audit-art-assets.mjs`会生成`output/art-refresh/asset-manifest.json`，列出实际文件的尺寸、SHA-256、用途、引用、生成记录与状态，并报告版本旁路候选和重复内容。脚本只读素材并写报告，不移动或删除文件。被图像工具拦截的3个商品保留原图，单独标明未更新。完成全组替换或重新截图后再次运行，以实际磁盘内容为准。
